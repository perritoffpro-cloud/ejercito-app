1 Visión General y Propósito del Sistema

El Centro de Mando del Ejército del Perú es un sistema integral de comando y control diseñado para la gestión operativa: registro jerárquico de cadetes, cronogramas de entrenamiento físico y táctico, calendario de ceremonias y el proceso de admisión de postulantes mediante transacciones atómicas seguras.

2 Arquitectura MVC Profesional (Modelo - Vista - Controlador)

El proyecto aplica una estricta separación de capas entre el servidor backend y el cliente web:

Capa / Carpeta Responsabilidad Técnica Archivos Principales
backend/src/models/ Capa de Acceso a Datos. Ejecuta sentencias SQL parametrizadas y transacciones atómicas. cadeteModel.js, rutinaModel.js, inscripcionModel.js, eventoModel.js
backend/src/controllers/ Capa de Lógica de Negocio. Procesa req y res, valida reglas y orquesta modelos. cadeteController.js, inscripcionController.js, uploadController.js

3 Conexión y Pool de Base de Datos (backend/src/config/db.js)

Para evitar abrir sockets TCP por cada usuario, se implementó un Pool de conexiones persistentes: 

import mysql from 'mysql2/promise';
import 'dotenv/config';

export const pool = mysql.createPool({
  host: process.env.DB_HOST || 'localhost',
  port: Number(process.env.DB_PORT) || 3306,
  user: process.env.DB_USER || 'root',
  password: process.env.DB_PASS || '',
  database: process.env.DB_NAME || 'ejercito_bd',
  dateStrings: true,        // 👈 Crucial: Mantiene fechas en formato YYYY-MM-DD sin desfases UTC
  connectionLimit: 10,      // 👈 Capacidad para atender hasta 10 peticiones concurrentes simultáneas
});
🗣️ Qué decir en este punto:
"Profesor, en backend/src/config/db.js configuramos un Pool de 10 conexiones con mysql2/promise. Esto optimiza el rendimiento reutilizando conexiones en memoria. Además, establecimos dateStrings: true para resolver de raíz el desfase de zona horaria de JavaScript, garantizando que las fechas de eventos se muestren con exactitud en la hora de Perú."

4 Capas del MVC en Acción: Modelos y Controladores

En la arquitectura MVC, el código está desacoplado: los modelos no conocen Express y los controladores no escriben SQL directo:

Separación de Responsabilidades:
  • Modelos (src/models/): Encapsulan consultas SQL puras con marcadores posicionales (?) contra SQL Injection.
  • Controladores (src/controllers/): Validan el DNI a 8 dígitos numéricos y limpian imágenes huérfanas en disco al actualizar o borrar.
  • Rutas (src/routes/): Enrutamiento semántico RESTful montado en /api.
// backend/src/controllers/cadeteController.js
export const cadeteController = {

      const nuevo = await cadeteModel.create(req.body);
      res.status(201).json(nuevo);

5 La Joya del Backend: Transacciones ACID y Bloqueo Concurrente

El punto de mayor valor técnico es la incorporación militar en backend/src/models/inscripcionModel.js: 

// backend/src/models/inscripcionModel.js -> aprobar(id)
const conn = await pool.getConnection(); // 1. Conexión dedicada del pool
try {
  await conn.beginTransaction(); // 2. INICIO DE TRANSACCIÓN ATÓMICA

  // 3. BLOQUEO PESIMISTA: Previene condiciones de carrera si dos administradores aprueban al mismo tiempo
  const [[i]] = await conn.query('SELECT * FROM inscripciones WHERE id=? FOR UPDATE', [id]);
  if (!i) throw createError(404, 'Inscripción no encontrada');
  if (i.estado === 'Aprobado') throw createError(409, 'El postulante ya fue aprobado');
  if (!i.eval_medica?.startsWith('Apto')) throw createError(400, 'Se requiere evaluación médica "Apto"');

  // 4. Buscamos el rango inicial "Soldado"
  const [[soldado]] = await conn.query("SELECT id FROM rangos WHERE nombre='Soldado'");

  // 5. Insertamos al nuevo cadete con su calificación de admisión
  const [c] = await conn.query(
    `INSERT INTO cadetes (nombres,apellidos,dni,rango_id,nivel,fisico,tactico,disciplina,unidad,fecha_ingreso,imagen)
     VALUES (?,?,?,?, 'Nuevo', ?, 0, 0, 'Centro de Instrucción', CURDATE(), ?)`,
    [i.nombres, i.apellidos, i.dni, soldado.id, i.eval_fisica || 0, i.imagen]);

  // 6. Vinculamos el ID del cadete y marcamos la inscripción como Aprobada
  await conn.query("UPDATE inscripciones SET estado='Aprobado', cadete_id=? WHERE id=?", [c.insertId, i.id]);

  await conn.commit(); // 7. CONFIRMACIÓN ATÓMICA DE AMBAS OPERACIONES
  return { ok: true, cadete_id: c.insertId };
} catch (e) {
  await conn.rollback(); // 8. Si ocurre cualquier error, se revierte todo al 100%
  throw e;
} finally {
  conn.release(); // 9. Devolvemos la conexión al pool
}
🗣️ Qué decir en este punto:
"El endpoint de aprobación implementa una Transacción ACID completa con bloqueo pesimista FOR UPDATE. Esto garantiza que si dos oficiales aprueban al mismo postulante en simultáneo, uno esperará al otro sin duplicar datos. Si cualquier paso fallara, el rollback() asegura que nunca tengamos postulantes marcados como aprobados sin su correspondiente cadete creado."

Diseñamos una arquitectura Full-Stack desacoplada: un Backend RESTful con patrón MVC en Node.js/Express y un Frontend SPA con React y Vite, sobre una base de datos relacional MySQL 8."

⏱️ Minuto 2: Manejo de Conexiones y Desacoplamiento (backend/src/config/db.js)

"En config/db.js configuramos un Pool de 10 conexiones con mysql2/promise. Esto reutiliza hilos de conexión abiertos en memoria evitando la latencia de re-autenticación TCP. "En src/models/ residen exclusivamente las consultas a la base de datos usando sentencias preparadas con signos de interrogación (?), haciendo al sistema invulnerable a SQL Injection. En src/controllers/ validamos la integridad de datos, como el DNI de 8 dígitos numéricos, y eliminamos fotos huérfanas en disco al actualizar."

⏱️ Minuto 4: Lógica de Negocio y Transacciones ACID

"El flujo más importante es la incorporación militar. En inscripcionModel.js aplicamos una transacción atómica con conn.beginTransaction() y bloqueo FOR UPDATE. Se valida la aptitud médica, se asigna el rango inicial de 'Soldado', se crea el cadete y se actualiza la inscripción, todo en una unidad indivisible de trabajo."

"Al ejecutar npm run dev, se inician en paralelo el Backend en el puerto 3000 y el Frontend en el puerto 5173. Podemos verificar los datos en tiempo real consumiendo http://localhost:3000/api/cadetes y comprobar la sincronización inmediata con la interfaz React."

8 Banco de Preguntas Difíciles del Jurado y Respuestas Maestras

Respuestas técnicas y precisas para las preguntas más frecuentes durante una sustentación:

❓ Pregunta 1: "¿Por qué utilizaste un Pool de conexiones en lugar de una conexión directa?"
"Porque un servidor web atiende múltiples peticiones simultáneas. Una conexión individual obligaría a encolar las peticiones de forma síncrona. El Pool de conexiones de mysql2 administra un grupo de conexiones precalentadas (10 en nuestro caso), prestando una conexión disponible a cada cliente y recuperándola con release()."
❓ Pregunta 2: "¿Cómo garantizas la protección contra Inyección SQL?"
"En ningún punto del backend se realiza concatenación de strings en las sentencias SQL. El 100% de las operaciones se ejecutan mediante consultas preparadas con marcadores de posición ?. La librería mysql2 envía la estructura SQL y los datos por canales separados, impidiendo cualquier inyección de código arbitrario."
❓ Pregunta 3: "¿Por qué la aprobación requiere una Transacción ACID con FOR UPDATE?"
"Porque involucra dos tablas críticas (inscripciones y cadetes). ACID garantiza: Atomicidad (se ejecutan ambas o ninguna), Consistencia (se validan reglas como examen médico 'Apto'), Aislamiento (FOR UPDATE bloquea la fila para evitar que dos operadores aprueben al mismo postulante en paralelo) y Durabilidad (los cambios persisten con commit())."
❓ Pregunta 4: "¿Cómo se comunican el Frontend y el Backend en desarrollo?"
"El frontend en React corre sobre Vite en el puerto 5173 y el backend Express en el puerto 3000. Para evitar problemas de CORS y simular un dominio unificado de producción, configuramos un Proxy inverso en frontend/vite.config.js que redirige de forma transparente todas las peticiones hacia /api y /assets al servidor backend."
