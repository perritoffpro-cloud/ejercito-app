1 Visión General y Propósito del Backend

El backend del Centro de Mando del Ejército del Perú centraliza, valida y sirve de forma transaccional toda la información operativa institucional: control de cadetes, cronograma de entrenamientos físicos y tácticos, calendario de eventos militares y admisión de nuevos reclutas con validación médica previa.

2 Arquitectura de Archivos y Responsabilidades

Siguiendo estándares de desarrollo profesional, el sistema elimina redundancias y micro-archivos dispersos agrupando la lógica en dos módulos de alta cohesión:

Archivo Responsabilidad Técnica Principios y Patrones Aplicados
server/db.js Gestión del Pool de conexiones MySQL y mapeo estricto de tipos de fecha. Patrón Singleton de Pool, desacoplamiento con .env, solución de desfase horario UTC.
server/index.js API RESTful Express, CRUD genérico, transacciones ACID y gestión de archivos. Principio DRY (Factory Pattern), sentencias preparadas contra SQL Injection, rollback seguro.
database/ejercito_bd.sql Esquema DDL relacional maestro, llaves foráneas con integridad referencial y seeds. Normalización 3NF, motor transaccional InnoDB, juego de caracteres utf8mb4.

3 Conexión y Pool de Base de Datos (server/db.js)

En producción, una aplicación profesional jamás abre y cierra conexiones por petición. Se implementó un Pool de conexiones persistentes con mysql2/promise: 

import mysql from 'mysql2/promise';
import 'dotenv/config';

export const pool = mysql.createPool({
  host: process.env.DB_HOST || 'localhost',
  port: Number(process.env.DB_PORT) || 3306,
  user: process.env.DB_USER || 'root',
  password: process.env.DB_PASS || '',
  database: process.env.DB_NAME || 'ejercito_bd',
  dateStrings: true,        // 👈 Crucial: Devuelve fechas YYYY-MM-DD sin desfases por zona horaria
  connectionLimit: 10,      // 👈 Capacidad para atender hasta 10 clientes concurrentes instantáneos
});
🗣️ Qué decir en este punto:
"Profesor, en server/db.js configuramos un Pool de 10 conexiones con mysql2/promise. Esto optimiza drásticamente el rendimiento reutilizando sockets TCP abiertos en memoria. Además, activamos dateStrings: true para resolver de raíz el clásico desfase de zona horaria de JavaScript, garantizando que las fechas de eventos y nacimientos se muestren exactamente como están registradas en Perú."

4 Arquitectura DRY: La Función Fábrica crud()

En lugar de duplicar 80 líneas de código para cada entidad (Cadetes, Rutinas, Eventos, Inscripciones), creamos en server/index.js un generador de controladores RESTful (Factory Pattern):

Beneficios Técnicos de la Fábrica crud():
  • Inmunidad contra SQL Injection: 100% de consultas parametrizadas con marcadores de posición ?.
  • Validaciones Centralizadas: DNI estrictamente validado a 8 dígitos numéricos mediante Regex.
  • Higiene de Archivos: La función deleteOldImage() elimina fotos huérfanas en /assets al actualizar o borrar.
mount('/cadetes', crud('cadetes',
  ['nombres', 'apellidos', 'dni', 'rango_id', 'nivel', 'fisico', 'tactico', 'disciplina', 'unidad', 'fecha_ingreso', 'imagen'],
  { select: 'SELECT cadetes.*, rangos.nombre AS rango, rangos.orden FROM cadetes JOIN rangos ON rangos.id = cadetes.rango_id',
    order: 'rangos.orden DESC, cadetes.apellidos' }));

mount('/rutinas', crud('rutinas', ['titulo', 'tipo', 'frecuencia', 'dia_semana', 'hora', 'duracion_min', 'rango_id', 'nivel', 'descripcion', 'imagen']));
mount('/eventos', crud('eventos', ['titulo', 'tipo', 'fecha', 'hora', 'lugar', 'descripcion', 'imagen']));
mount('/inscripciones', crud('inscripciones', ['nombres', 'apellidos', 'dni', 'fecha_nacimiento', 'telefono', 'direccion', 'talla_cm', 'peso_kg', 'eval_medica', 'eval_fisica', 'estado', 'imagen']));

5 La Joya del Backend: Transacciones ACID y Concurrencia

El punto de mayor valor técnico del proyecto es la incorporación de postulantes (POST /api/inscripciones/:id/aprobar): 

app.post('/api/inscripciones/:id/aprobar', wrap(async (req, res) => {
  const conn = await pool.getConnection(); // 1. Conexión dedicada del pool
  try {
    await conn.beginTransaction(); // 2. INICIO DE TRANSACCIÓN ATÓMICA

    // 3. BLOQUEO PESIMISTA: Previene condiciones de carrera si dos administradores aprueban al mismo tiempo
    const [[i]] = await conn.query('SELECT * FROM inscripciones WHERE id=? FOR UPDATE', [req.params.id]);
    if (!i) return res.status(404).json({ error: 'Inscripción no encontrada' });
    if (i.estado === 'Aprobado') return res.status(409).json({ error: 'El postulante ya fue aprobado' });
    if (!i.eval_medica?.startsWith('Apto')) {
      return res.status(400).json({ error: 'Se requiere evaluación médica "Apto" para aprobar' });
    }

    // 4. Buscamos el rango inicial "Soldado"
    const [[soldado]] = await conn.query("SELECT id FROM rangos WHERE nombre='Soldado'");

    // 5. Insertamos al nuevo cadete con su calificación física de ingreso
    const [c] = await conn.query(
      `INSERT INTO cadetes (nombres,apellidos,dni,rango_id,nivel,fisico,tactico,disciplina,unidad,fecha_ingreso,imagen)
       VALUES (?,?,?,?, 'Nuevo', ?, 0, 0, 'Centro de Instrucción', CURDATE(), ?)`,
      [i.nombres, i.apellidos, i.dni, soldado.id, i.eval_fisica || 0, i.imagen]);

    // 6. Vinculamos el ID del cadete y marcamos como aprobado
    await conn.query("UPDATE inscripciones SET estado='Aprobado', cadete_id=? WHERE id=?", [c.insertId, i.id]);

    await conn.commit(); // 7. CONFIRMACIÓN ATÓMICA DE AMBAS OPERACIONES
    res.json({ ok: true, cadete_id: c.insertId });
  } catch (e) {
    await conn.rollback(); // 8. Si algo falla, se cancela y revierte todo
    throw e;
  } finally {
    conn.release(); // 9. Devolvemos la conexión al pool
  }
}));
🗣️ Qué decir en este punto:
"Aquí reside el máximo rigor técnico de nuestro backend: la incorporación de postulantes implementa una Transacción ACID. Utilizamos la sentencia FOR UPDATE para bloquear la fila en lectura, previniendo condiciones de carrera si dos administradores hicieran clic al mismo tiempo. Si cualquier paso fallara, el bloque catch dispara un rollback() automático impidiendo inconsistencias o registros a medio guardar."

El objetivo del diseño fue lograr máxima robustez, arquitectura modular DRY y estricta integridad referencial."

⏱️ Minuto 2: Manejo de Conexiones y Rendimiento (server/db.js)

"En server/db.js configuramos un Pool de 10 conexiones con mysql2/promise. Esto evita abrir y cerrar sockets TCP por cada petición, reduciendo la latencia a milisegundos. Añadimos dateStrings: true para resolver de forma definitiva el problema de zonas horarias de JavaScript y mantener las fechas consistentes con la hora peruana."

⏱️ Minuto 3: Modularidad y Seguridad contra SQL Injection (server/index.js)

"En lugar de repetir el código CRUD en cada módulo, diseñamos la fábrica crud(). Esta genera los endpoints RESTful para Cadetes, Rutinas, Eventos e Inscripciones. El 100% de consultas utilizan sentencias preparadas con signos de interrogación (?), lo que hace al sistema totalmente inmune a ataques de SQL Injection."

⏱️ Minuto 4: Lógica de Negocio y Transacciones ACID

"El flujo más importante es la aprobación del recluta. Aplicamos una transacción atómica con conn.beginTransaction() y bloqueo FOR UPDATE. Validamos que su ficha médica esté en estado 'Apto', le asignamos el rango inicial de 'Soldado', creamos su registro de cadete y actualizamos la inscripción, todo en una sola unidad indivisible de trabajo."

⏱️ Minuto 5: Demostración Práctica en Vivo

"Podemos comprobar el funcionamiento en vivo ingresando a http://localhost:3000/api/cadetes. Observamos la respuesta JSON en tiempo real con los cadetes registrados, sus notas ponderadas, el JOIN con la tabla de rangos y los enlaces a las fotos servidas desde /assets."

8 Banco de Preguntas Difíciles del Jurado y Respuestas Maestras

Respuestas técnicas y precisas para las preguntas más frecuentes durante una sustentación:

❓ Pregunta 1: "¿Por qué utilizaste un Pool de conexiones en lugar de una conexión directa?"
"Porque un servidor web atiende múltiples peticiones simultáneas. Una conexión individual obligaría a encolar las peticiones de forma síncrona, generando cuellos de botella. El Pool de conexiones de mysql2 administra un conjunto precalentado de conexiones (10 en nuestro caso), entregando una conexión disponible a cada cliente y recuperándola de inmediato con release()."
❓ Pregunta 2: "¿Cómo garantizas la protección contra Inyección SQL?"
"En ningún punto del backend se realiza concatenación manual de strings en las sentencias SQL. El 100% de las operaciones se ejecutan mediante consultas preparadas con marcadores de posición ?. La librería mysql2 envía la estructura SQL y los datos por canales separados al motor de base de datos, impidiendo cualquier ejecución arbitraria de código."
❓ Pregunta 3: "¿Por qué la aprobación requiere una Transacción ACID con FOR UPDATE?"
"Porque involucra dos tablas críticas (inscripciones y cadetes). ACID garantiza: Atomicidad (se ejecutan ambas o ninguna), Consistencia (se validan reglas como examen médico 'Apto'), Aislamiento (FOR UPDATE bloquea la fila para evitar que dos operadores aprueben al mismo postulante en paralelo) y Durabilidad (los cambios persisten con commit())."
❓ Pregunta 4: "¿Por qué activaste dateStrings: true en el driver de base de datos?"
"Por defecto, el driver convierte las fechas a objetos Date de JavaScript interpretados en UTC (Meridiano 0). Como el Perú está en la zona horaria UTC-5, al exportar a JSON las fechas retrocedían un día (el 24 de noviembre aparecía como 23 de noviembre). Con dateStrings: true, MySQL entrega la fecha como texto exacto YYYY-MM-DD sin desfases."
